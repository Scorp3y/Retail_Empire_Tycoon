# Этап 7 — профилирование и финальная приёмка города

Статус: выполнены два графических прогона изолированного Unity Play Mode. Этап **не завершён**: Windows Player и достоверное GPU-время пока не получены. Производственная застройка и игровой код не менялись, оптимизация по неполным данным не применялась.

## Что реализовано

Добавлен воспроизводимый измерительный сценарий: копия настоящего Game без SaveManager и компонентов обучения → настоящий CityTrip.Begin → семь игровых/обзорных камер → CityTrip.Return. Временная сцена создаётся только в изолированном проекте. Идентификатор приложения отделён от настоящей игры; настройки копии восстанавливаются побайтно даже при ошибке. Обычный запуск игры не включает измеритель: нужен явный аргумент `-town-profile-out`, разрешённый только внутри тестовой копии/сборки. В Release измеритель исключён из компиляции.

Перед каждым ракурсом: 3 секунды прогрева, затем 8 секунд измерения. Буферы измерителя подготовлены до прогрева; CSV и PNG записываются после измеряемого интервала. Сохраняются исходные кадры измерения, доступность каждого счётчика, параметры камеры, устройство и контрольные суммы источников. Повторный запуск не перезаписывает прежние доказательства.

Второй прогон дополнительно считает реальные события `endCameraRendering`. Во всех семи ракурсах число событий равно числу измеренных обновлений: покрытие 100%. Это подтверждает отправку рендера камеры каждый кадр, но не заменяет измерение GPU и вывода изображения на монитор.

## Условия и границы достоверности

- Unity 2022.3.62f3, Windows, изолированный Editor Play Mode в batchmode; **не standalone Player**.
- Intel i7-12650H, NVIDIA RTX 3050 Laptop, Direct3D11; системная память 16085 МБ, видеопамять 3962 МБ.
- Фактически выбран профиль **Ultra / Town Graphics Ultra**. VSync отключён, ограничитель кадров отключён только в тесте.
- Город отрисовывается штатным render loop в RenderTexture 1920×1080. HUD остаётся на backbuffer редактора 640×480 и не входит в PNG камеры. Это не эквивалент обычной игры с HUD 1920×1080.
- Другие четыре экземпляра Unity оставались открыты. Пользовательские редакторы не закрывались; их фоновая нагрузка не контролировалась.
- `FrameTimingManager` не вернул валидных GPU-таймингов. Счётчик `GPU Frame Time` тоже не дал положительных значений. CPU render-thread time недоступен. В JSON/CSV недоступность обозначена `-1`, не нулевой нагрузкой.
- `Main Thread` — маркер главного потока редактора, включает его накладные расходы. `CPU Main Thread Frame Time` получен отдельным штатным счётчиком. Среднее CPU ниже не является временем GPU или полной интерактивной игры.
- Числа `loopFps` в сыром JSON — частота тестового цикла; **не заявленный игровой FPS**. Память и выделения GC относятся ко всему процессу Editor, не только к городу.

Unity описывает ограничения и накладные расходы таймингов в [Frame Timing Manager](https://docs.unity3d.com/2022.3/Documentation/Manual/frame-timing-manager.html). Наличие и единицы счётчиков получены через [ProfilerRecorder](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Unity.Profiling.ProfilerRecorder.html); полный каталог сохранён с каждым прогоном.

Главный вывод: обзор города и набережная требуют больше отрисовки, чем ограниченный вид двора. **GPU-узкое место не установлено.** Удалять дома, отключать коллизии или уменьшать качество теней на этом основании нельзя. Следующая оптимизация должна начинаться с standalone CPU/GPU-профиля и конкретного измеренного источника затрат.

## Windows-сборка: незакрытое ограничение

Исправлен первоначально недопустимый для Unity путь вывода внутри Library: сборка направлена в `Builds/TownPerformancePlayer` изолированного проекта. После компиляции Player scripts две попытки остановились на штатном BuildPlayerDataGenerator. Его дочерний netcorerun находился в состоянии **Waiting / Suspended**, CPU = 0, без прогресса. Прямой запуск того же штатного генератора с аргументами Unity успешно создал RuntimeInitializeOnLoads.json и TypeDb-All.json, но повторная сборка снова остановилась на дочернем запуске.

Причина остановки дочернего процесса пока не установлена: это наблюдение, не доказательство ошибки Windows Defender, Unity или проекта. Только собственные зависшие тестовые процессы были завершены; настройки копии восстановлены побайтно. Успешная Windows-сборка, standalone FPS/GPU-профиль и сравнение до/после **не заявляются**. Системная защита не отключалась, suspended-процессы принудительно не возобновлялись.
