# TownKit: отдельный набор low-poly моделей

## Результат и границы

Созданы 88 реальных 3D-моделей. Они находятся в `Assets/Art/TownKit` и **не размещены на игровых сценах**. Существующие игровые префабы, каталоги покупок и сохранения игрока не меняются. Терминал выдачи заказов и отдельный указатель направления к поставщикам, вычеркнутые из концепта, исключены. Обычные дорожные знаки и знак выдачи заказов оставлены.

Это самостоятельные геометрические low-poly модели по согласованному визуальному направлению: светлые и кирпичные фасады, мятные крыши, тёмные рамы, деревянные и металлические предметы. Это не изображения, нанесённые на плоские карточки, и не точные копии концепт-арта.

## Как просмотреть и использовать

- `index.html` — галерея всех моделей с русскими названиями, размером, числом треугольников и ссылками на OBJ.
- `Previews/AllModels.png` — общий лист; отдельные листы категорий и рендер каждого объекта находятся рядом.
- `Prefabs/<категория>` — префабы Unity с готовым материалом.
- `Meshes/<категория>` — собственная геометрия префабов; OBJ не нужен для их работы.
- `Models/<категория>` — переносимые OBJ; общий `Models/TownKit.mtl` ссылается на `Materials/TownPalette.png`. При переносе вне Unity сохраняйте относительное расположение этих папок.
- `manifest.json` — полный состав набора, размеры и пути.

Масштаб: одна единица Unity — один метр. Вертикаль +Y, передняя сторона +Z. Нижняя точка геометрии находится на Y=0. Основные дорожные модули имеют шаг 12 м и проезжую часть 8 м. Обычное парковочное место — 2,8 × 5,6 м. Декоративная дорожная разметка не предназначена для физической коллизии.

Все детали одной модели объединены в одну геометрию: один MeshRenderer и один общий материал URP/Lit с небольшой цветовой палитрой. Это уменьшает число объектов отрисовки, но **не гарантирует один вызов отрисовки на весь город**: тени, камера и настройка рендера тоже влияют на нагрузку.

Префабы содержат только визуальную часть: без контроллеров автомобилей, анимаций ворот, интерактивных дверей, коллайдеров, складской логики и триггеров покупки. Стёкла условно непрозрачные стилизованные. Здания поставщиков — внешние оболочки; интерьер не моделировался. PlayerShopShell — отдельная визуальная заготовка, не замена редактируемой постройки магазина игрока. Функциональные компоненты и физические ограничения следует подключать отдельным этапом после утверждения моделей.

## Воспроизводимая генерация

Генератор находится в `Assets/Project/Editor/TownKit`. Геометрия строится из явных форм и палитры; каталог задаёт состав, экспорт сохраняет OBJ, а временные несохраняемые preview-сцены дают реальные рендеры моделей.

Безопасный путь данных:

`TownAssetCatalogue → генераторы геометрии → Mesh + prefab + OBJ → импорт и проверки Unity → рендеры + галерея → перенос только TownKit в основной проект`.

Скрипт `Scripts/GenerateTownKit.ps1` использует существующую изолированную копию Unity в `Library/CityUpdateQA/IsolatedProject`, Unity 2022.3.62f3 и PowerShell 7:

```powershell
./Scripts/GenerateTownKit.ps1 -Mode Prepare
./Scripts/GenerateTownKit.ps1 -Mode Launch
./Scripts/GenerateTownKit.ps1 -Mode Apply
```

Prepare копирует исходники генератора и записывает контрольные суммы сцен. Launch запускает изолированный редактор без сохранения игровых сцен. Apply требует успешный отчёт, неизменные исходники генератора и сцены; переносит только готовые ассеты. При параллельном изменении существующего ассета перенос прекращается, пользовательская версия не перезаписывается. Повторная генерация сохраняет GUID уже существующих собственных Mesh/Prefab ассетов.

Автоматически проверяются уникальность ID, исключённые объекты, конечные координаты, наличие нормалей и UV, отсутствие нулевых треугольников, опорная высота, ограничение сложности, состав префабов, наличие рендеров и совпадение количества треугольников после импорта OBJ. Результат находится в `Library/TownKitQA/result.txt`.
