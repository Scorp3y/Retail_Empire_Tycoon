# Интерфейс и вход в магазин

## Решения

Персонал — отдельное представление существующего `ShopWindow`, а не второй модальный экран поверх Store. Кнопка есть только в главном меню Store. Сам ShopWindow отвечает за блокировку камеры и возврат к категориям; HUD отображает правила найма из StaffRoster. Уровень магазина остаётся внутренним правилом лимитов, но не выводится в интерфейсе.

Рейтинг использует пять пар существующих спрайтов GUI_24 / GUI_25. Заполненная часть звезды отражает дробный рейтинг. Состояние открытия показывается двумя одинаково оформленными векторными замками. Тысячи не сокращаются, суффиксы начинаются с миллиона.

Выкладка: выбор продукта → пять товарных слотов → предпросмотр дочерним объектом слота → подтверждение пятого действия → перенос реального остатка со склада. Предпросмотр и обычное заполнение используют один метод создания модели, поэтому наследуют одинаковые поворот и масштаб. Камера центрируется на всех слотах полки и выбирает ракурс без посторонних физических препятствий. При отмене товар не списывается.

Навигация: цель NPC → ближайшие проходимые клетки → поиск пути с приоритетом в сторону цели → проверка каждого перехода по физическим препятствиям → движение. Занятые клетки стен недоступны; у двери проходим только центральный проём, а не боковые стойки. ShopCharacter и старый Avatar используют StoreNavigation. Покупатели появляются перед входом и уходят туда же. При приближении открываются створки; после прохода они закрываются. Касса выбирает свободное место внутри магазина, не ближе 1.05 единицы от входа.

## Проверка и ограничения

Деньги при запуске: SaveManager загружает баланс в MoneyController → событие Changed обновляет MoneyView и совместимый GameManager. При повторном включении интерфейса берётся текущий баланс. Значение playerMoney синхронизируется с кошельком, отдельного опроса в Update нет.

Движение проверяется капсулой радиуса 0.075 и высоты текущих магазинных моделей: низкие швы пола не блокируют тело, но даже тонкая высокая преграда требует обхода. Дверные клетки ограничены центральной полосой. Avatar использует тот же ShopCharacter для движения. При временной блокировке цель сохраняется, Arrived остаётся false, поиск повторяется не чаще раза в 0.4 секунды. Остаток движения переносится между клетками в пределах кадра, чтобы скорость не зависела от количества точек. Полки выбираются с учётом физических размеров, лицевой стороны и доступного маршрута; двусторонняя полка допускает оба подхода. Отмена задания сотрудника останавливает движение и анимацию.

Новые проверки: `Validate startup and movement in sandbox` (баланс, повторное включение HUD, шов пола, тонкий столбик, скорость при 10/60 Гц, блокировка и восстановление пути). Отчёт: `Library/ShopGameplayQA/startup-movement.txt`.

Проверки выполняются в `ShopGameplaySandbox`, где отсутствует SaveManager. Планировка игрока загружается только для чтения. Команды доступны в меню Retail Empire / Shop: Validate gameplay, Validate work UI input, Preview milk restocking, Preview bread restocking.

Требуется физическая геометрия препятствий: объект без Collider и без строительной занятости не может блокировать маршрут. Поиск ограничен 20000 посещённых клеток; при недоступной цели NPC останавливается, а не проходит через стену. Кадрирование проверено на текущей планировке; произвольная тесная расстановка может потребовать дополнительного выбора ракурса.
# Покупная касса

`CashRegister.asset` находится в Structures: $300, 3×3 клетки, существующая модель Market kit. Карточка магазина добавляет предмет в строительный инвентарь; обычный BuildController проверяет размещение и сохраняет его по `cash_register_01`. Предмет добавлен также в каталог восстановления сохранений.

После выхода из строительства StoreOperations выбирает ближайшую доступную установленную кассу и строит маршрут к её передней стороне. Для старых сохранений без доступной покупной кассы остаётся прежняя автоматическая станция. Сейчас обслуживается одна активная касса, отдельные очереди для нескольких касс не реализованы. Персонал доступен с главной страницы магазина, а не среди категорий строительства.

Проверка: `Retail Empire/Shop/Validate checkout catalog in sandbox` в изолированной сцене Play Mode. Проверяет карточку, обе ветки покупки, инвентарь, сетку, активную точку обслуживания, маршрут, запись размещения и кнопку персонала. Отчёт: `Library/ShopGameplayQA/checkout.txt`.
